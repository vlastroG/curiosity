# Crypto Watch

День 18: «Планировщик и фоновые задачи». Агент работает 24/7: раз в N минут берёт у MCP-сервера
свежие курсы криптовалют, просит языковую модель сделать прогноз и показывает его в браузере.

```
браузер ◄── /api ──► crypto-watch ──(каждые N мин)──► модель ◄── tool calls ──┐
                        │ settings.json                                         │
                        └──── MCP: summary / series / schedule / forecasts ─────► mcp-crypto ──(каждые N мин)──► Binance
                                                                                     └── SQLite
```

Роли разделены:

- [**mcp-crypto**](../mcp-crypto) отвечает за данные. Фоновый планировщик сам снимает цены в SQLite,
  инструменты отдают агрегаты. Модель ему не нужна.
- **crypto-watch** отвечает за прогноз и интерфейс. Цикл 24/7 будит модель, модель сама вызывает
  `crypto_summary` (и, если нужно, `crypto_series`) и возвращает прогноз в JSON. Агент проверяет
  ответ, сохраняет его через `save_forecast` и показывает на странице.

## Что на странице

- **Сейчас** — карточка на каждую монету: цена, изменение за окно, график, минимум и максимум,
  волатильность.
- **Прогноз на 30 минут** — общий комментарий модели. По каждой монете: тренд, диапазон цены
  на шкале рядом с текущей ценой, уверенность, причина. Ниже видно, какие MCP-инструменты
  вызывала модель, сколько она думала и сколько потратила токенов.
- **История прогнозов** — последние десять, каждый раскрывается.

Настройки меняются прямо на странице и сохраняются в `settings.json`:

| Настройка | Значения | По умолчанию |
|---|---|---|
| Частота | 1–15 мин: с ней MCP-сервер собирает цены, а агент делает прогноз | 1 мин |
| Окно анализа | 15 мин – 4 ч: столько истории модель учитывает при прогнозе | 1 ч |
| Модель | бесплатные модели OpenRouter и DeepSeek | Nemotron 3 Super (free) |

Частота одна на двоих. При её смене бэкенд вызывает у MCP-сервера `crypto_schedule`, и сервер
перезаводит свой таймер. Модели без ключа в `.env` видны в списке, но выбрать их нельзя.

## Запуск

Ключи лежат в общем `.env` в корне репозитория (см. `.env.example`). Для бесплатных моделей
нужен `OPENROUTER_API_KEY`, для DeepSeek — `DEEPSEEK_API_KEY`.

```bash
docker compose up --build -d
```

Страница: http://localhost:5175. MCP-сервер доступен и напрямую: http://localhost:8766/mcp.

Оба контейнера запускаются с `restart: unless-stopped`: после сбоя или перезагрузки Docker
поднимает их сам. История цен, прогнозы и настройки лежат на томах и переживают пересборку.

Логи показывают оба расписания:

```bash
docker compose logs -f
```

```
mcp-crypto   | планировщик: собрано 5 цен
crypto-watch | прогноз: модель nvidia/nemotron-3-super-120b-a12b:free, окно 60 мин
crypto-watch | прогноз #2 готов за 24.1 с, шагов 2: За последние 60 минут цены …
```

### Разработка без Docker

```bash
cd ../mcp-crypto && PORT=8766 go run .
cd backend && go run ./cmd/server        # :8080, MCP по умолчанию http://localhost:8766/mcp
cd frontend && npm install && npm run dev # :5176, /api проксируется на :8080
```

## Как устроен прогноз

1. Код берёт `crypto_summary` за окно. Из сводки берутся цены на момент прогноза и список монет.
   Если данных ещё нет, модель не вызывается.
2. Модель получает инструменты `crypto_summary` и `crypto_series`. Сохранять прогнозы и менять
   расписание ей нельзя, это делает код. Если модель ответила, не заглянув в данные, её просят
   сначала посмотреть данные.
3. Ответ — JSON: `overview` и по каждой монете `trend`, `low`, `high`, `confidence`, `reason`.
   Если JSON не разобрался, модель получает одну повторную попытку. Затем код нормализует ответ:
   монеты, которых нет в данных, отбрасываются, `low` и `high` упорядочиваются, уверенность
   ограничивается диапазоном 0…1.
4. Прогноз сохраняется в SQLite MCP-сервера (`save_forecast`).

Интервал отсчитывается от начала прогона. Бесплатная модель думает 20–60 секунд, и без этого
«раз в минуту» превратилось бы в «раз в две».

Горизонт прогноза задаёт `HORIZON_MINUTES` (по умолчанию 30). Первый прогноз после старта
запускается через `FIRST_DELAY` (по умолчанию 20 с), чтобы сервер успел собрать хотя бы одну точку.

## Тесты

```bash
cd backend && go test ./...
cd frontend && npm test && npm run build
```

Модель и MCP-сервер в тестах заменены заглушками. Проверяются цикл tool calls, повтор при ответе
не по формату, нормализация прогноза, повторы при 429, проверка настроек и их сохранение.

> Это учебный прогноз языковой модели по минутным ценам. Не инвестиционный совет.
