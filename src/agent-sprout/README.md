# Agent Sprout

Помощник начинающего строителя. Вы описываете, какие работы нужно выполнить, —
ассистент задаёт уточняющие вопросы, сверяет с вами собранное и выдаёт пошаговый
план работ с расчётом материалов, контролем качества и техникой безопасности.

Один разговор — один вид работ. Ассистент не возьмётся планировать, пока не соберёт
исходные данные, и не начнёт вторую задачу, не закончив первую.

## Возможности

**Задача с чеклистом.** По описанию работ ассистент составляет список исходных данных
(основание, объёмы, условия, материалы, инструмент, сроки) и опрашивает вас по нему.
Прогресс виден в полосе состояния над перепиской.

**Обязательная сверка перед планом.** Когда чеклист заполнен, собранное показывается
списком: что-то записано неверно — поправьте прямо в переписке, и ассистент покажет
поправленный список снова, отложив план. Плана не будет, пока вы не подтвердите
данные, и перепрыгнуть этот шаг ассистент не может.

**Профиль пользователя.** Кнопка «профиль» в шапке: кто вы, как с вами говорить,
как оформлять ответы и чего у вас нет. Действует во всех чатах сразу и меняет и стиль
ответов, и сам опрос — то, что написано в профиле, ассистент не спрашивает заново.

**Справочник знаний.** Общие для всех чатов правила и требования — «железобетон делаем
по СП 63». Есть готовые заготовки под частые виды работ: железобетон, кладка,
штукатурка, полы, кровля, фундаменты, охрана труда, расчёт материалов. Под каждую
задачу ассистент подбирает подходящие сам.

**Ветки диалога.** Кнопка «чекпоинт» клонирует чат со всей историей и собранными
данными. Удобно, когда объектов два: довели сбор до общей точки и дальше считаете
каждый отдельно.

**Погода с внешнего сервера.** Для наружных работ агент сам узнаёт фактические
условия на объекте — температуру, влажность, осадки и прогноз на несколько суток —
и учитывает их в плане: когда начинать, за сколько высохнет слой, нужна ли защита
от дождя. Данные берутся не из памяти модели, а с отдельного
[MCP-сервера](../mcp-weather), который ходит в метеослужбу; решение вызвать его
принимает сама модель, и вызов виден в трейсе под ответом. Город — в профиле,
выключатель — в настройках чата. На моделях, которые не умеют вызывать инструменты,
выключатель погашен.

**Видно, что происходит.** Под каждым ответом — что ассистент взял из профиля, знаний
и памяти диалога, сколько это стоило в токенах и деньгах и через какие этапы прошёл
запрос. Ничего не оценивается на глаз: все цифры приходят от провайдера модели.

## Быстрый старт

Нужен Docker и ключ хотя бы одного провайдера.

1. Создайте `.env` в корне репозитория (образец — `.env.example`):

   ```
   DEEPSEEK_API_KEY=sk-...
   OPENROUTER_API_KEY=sk-or-v1-...
   DEFAULT_MODEL=deepseek-flash
   ```

2. Запустите:

   ```bash
   docker compose -f src/agent-sprout/docker-compose.yml up --build
   ```

3. Откройте http://localhost:5173

Чаты, знания и профиль хранятся в docker-томе и переживают пересборку контейнера.

## Модели

| Модель | Провайдер | Вход (кеш-промах) | Выход | Контекст | Инструменты |
| --- | --- | --- | --- | --- | --- |
| `deepseek-flash` | DeepSeek | $0.3 | $1.2 | 1M | да |
| `deepseek-v4-pro` | DeepSeek | $1.32 | $3.96 | 1M | да |
| `liquid/lfm-2.5-2.6b:free` | OpenRouter | бесплатно | бесплатно | 65K | нет |

Цены — доллары за миллион токенов по пиковому тарифу; вне пиковых часов DeepSeek берёт
вдвое меньше. Модель выбирается в настройках каждого чата отдельно.

Хватает одного ключа из двух: модели провайдера без ключа видны в списке, но погашены.
Бесплатная модель OpenRouter годится для знакомства с интерфейсом, но планы на ней
заметно слабее, и погоду она не узнает: выбрать инструмент и собрать к нему аргументы
на 2.6B параметров не выходит.

## Настройка

| Переменная | По умолчанию | Зачем |
| --- | --- | --- |
| `DEEPSEEK_API_KEY` | — | ключ DeepSeek |
| `OPENROUTER_API_KEY` | — | ключ OpenRouter |
| `DEFAULT_MODEL` | первая доступная | модель новых чатов |
| `PORT` | `8080` | порт сервера внутри контейнера |
| `DATA_FILE` | `/data/chats.json` | где лежат чаты, знания и профиль |
| `STATIC_DIR` | `/app/web` | каталог собранного интерфейса |
| `LLM_TIMEOUT` | `5m` | потолок на один вызов модели |
| `TURN_TIMEOUT` | `8m` | потолок на ход целиком: ход — это несколько вызовов подряд |
| `APP_URL` | `http://localhost:5173` | адрес приложения для атрибуции запросов в OpenRouter |
| `MCP_WEATHER_URL` | — | адрес MCP-сервера погоды; пусто — инструментов у модели нет |
| `MCP_TIMEOUT` | `20s` | потолок на один поход к серверу инструментов |

Настройки самого чата — модель, `temperature`, бюджет вывода и потолок длины запроса —
правятся в интерфейсе и хранятся вместе с чатом.

## Разработка

```bash
cd src/agent-sprout/backend  && go run ./cmd/server          # :8080
cd src/agent-sprout/frontend && npm install && npm run dev   # :5174, прокси /api на :8080
cd src/mcp-weather           && PORT=8765 go run .           # :8765, погода по MCP
```

Порт dev-сервера сдвинут на 5174 намеренно: 5173 занимает контейнер.

Сервер погоды нужен не всегда: без `MCP_WEATHER_URL` бэкенд запускается как
и раньше, просто у модели не будет инструментов. С ним:

```bash
cd src/agent-sprout/backend && MCP_WEATHER_URL=http://localhost:8765/mcp go run ./cmd/server
```

Нужен Go 1.25 — его подтянет сам toolchain, если стоит версия постарше.

Тесты — без сети, ключей и запущенного сервера:

```bash
cd src/agent-sprout/backend  && go test ./... && go vet ./...
cd src/agent-sprout/frontend && npm test
```

Ключи провайдеров читает только серверный процесс: в отдаваемой странице, в бандле
и в ответах API их нет.

## Зависимости

Интерфейс на React и Vite. У бэкенда одна прямая зависимость:

| Пакет | Зачем |
| --- | --- |
| `github.com/modelcontextprotocol/go-sdk` | клиент MCP: транспорт, рукопожатие, вызов инструментов |

Всё остальное — стандартная библиотека: клиент к моделям, хранилище, HTTP-слой
и сам агент написаны без посредников. Косвенно SDK приносит ещё восемь пакетов —
`google/jsonschema-go` (схемы инструментов), `segmentio/asm` и `segmentio/encoding`
(быстрый json), `yosida95/uritemplate` (шаблоны адресов ресурсов), `golang.org/x/oauth2`,
`golang-jwt/jwt` (авторизация у серверов, которые её требуют), `golang.org/x/sync`,
`golang.org/x/sys` и `golang.org/x/time`. Полный список — в `backend/go.mod`.
