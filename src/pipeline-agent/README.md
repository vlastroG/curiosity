# HN Digest Agent

Готовит по теме, заданной по-русски, конспект обсуждений на [Hacker News](https://news.ycombinator.com)
на русском языке и сохраняет его в HTML-файл. Спросите «что обсуждают про Rust в вебе» —
агент сам подберёт английские ключевые слова, найдёт подходящие истории, прочитает главные
комментарии, переведёт и сожмёт их. Результат — страница, которую можно открыть
в браузере или переслать.

Работа идёт через инструменты MCP-сервера [mcp-pipeline](../mcp-pipeline):
`hn_search` → `summarize` → `save_to_file`. Порядок вызовов и аргументы выбирает языковая
модель. После каждого прогона агент проверяет по трассе, что данные дошли от поиска
до файла без подмены.

Пример результата:

```
что нового в локальных LLM на этой неделе
Конспект обсуждений Hacker News · запрос «on-device LLM» · 2026-09-24 16:26 UTC · историй: 3

  На этой неделе обсуждались подходы к запуску языковых моделей локально: от полнофункционального
  агента Ox, который взаимодействует с веб-сайтами от имени пользователя, до методов дистилляции …

1. Show HN: Ox — локальный агент, использующий интернет за тебя
   Show HN: Ox – A local agent that uses the internet for you · https://…
   …
```

## Как это работает

```
 терминал
 docker compose run --rm agent "что обсуждают про Rust в вебе"
    │
    ▼
 agent (CLI)                                         mcp-pipeline (MCP-сервер)
 ┌─────────────────────────────────┐                ┌────────────────────────────────────┐
 │ tools/list ──────────────────────────────────────►│ hn_search, summarize,              │
 │                                 │                │ save_to_file, list_files           │
 │ модель (PIPELINE_MODEL) решает: │                │                                    │
 │  hn_search{"rust web",365 дн.} ─────────────────►│ hn_search ──► Algolia HN API       │
 │  ◄── src_de4d…, 5 историй ──────────────────────  │   └► artifacts/src_de4d….json      │
 │  (мало или не по теме? —        │                │                                    │
 │   переформулирует и ищет снова) │                │                                    │
 │  summarize{"src_de4d…"} ────────────────────────►│ summarize ──► модель (PIPELINE_MODEL)
 │  ◄── sum_f379…, sha ✓ ──────────────────────────  │   └► artifacts/sum_f379….json      │
 │  save_to_file{"sum_f379…"} ─────────────────────►│ save_to_file                       │
 │  ◄── out/rust-web-….html ───────────────────────  │   └► out/rust-web-….html, index.html
 │                                 │                └────────────────────────────────────┘
 │ проверка цепочки:               │                 папка ./data (в контейнере /data)
 │  hn_search → summarize → save,  │                 ├─ artifacts/  промежуточные результаты
 │  id и sha256 совпадают,         │                 ├─ out/        HTML-конспекты
 │  файл есть на сервере → ✔       │                 └─ logs/       логи агента
 └─────────────────────────────────┘
```

Модель работает в двух местах:
- **агент** решает, что делать: переводит тему в поисковые слова, выбирает период
  и число историй, решает, переискать ли (не больше трёх поисков), придумывает имя файла;
- **summarize** на сервере пишет сам конспект: обзор, перевод заголовков, суть обсуждения
  и тезисы по каждой истории.

Между шагами передаются не тексты, а id артефактов (`src_…`, `sum_…`) с хешем sha256
содержимого. Каждый шаг проверяет свой вход, поэтому модель не может «пересказать своими
словами» выдачу при передаче в следующий инструмент или подсунуть чужой конспект.

## Требования

- Docker с Compose v2.
- Ключ [OpenRouter](https://openrouter.ai/keys): бесплатных моделей хватает для работы.
  Для моделей DeepSeek нужен ключ [DeepSeek](https://platform.deepseek.com/api_keys).

## Быстрый старт

1. В корне репозитория скопируйте `.env.example` в `.env` и впишите ключ:

   ```
   OPENROUTER_API_KEY=sk-or-v1-...
   ```

2. Запустите сервер (дальше он работает постоянно):

   ```bash
   docker compose up -d --build mcp-pipeline
   ```

3. Задайте тему:

   ```bash
   docker compose run --rm agent "что обсуждают про Rust в вебе"
   ```

Первый прогон занимает 30–90 секунд, больше всего времени уходит на конспект.

## Использование

**Один запрос.** Тема передаётся аргументом, агент завершается после ответа:

```bash
docker compose run --rm agent "что нового в локальных LLM на этой неделе"
```

**Интерактивно.** Без аргумента агент спрашивает темы по одной. Пустая строка или Ctrl+D
завершают сессию:

```bash
docker compose run --rm agent
```

```
запрос> как в индустрии относятся к удалённой работе
…
запрос> обзор споров про Kubernetes для маленьких команд
…
запрос>
```

Примеры тем:
- `что обсуждают про Rust в вебе` — поиск за последний год;
- `что нового в локальных LLM на этой неделе` — свежие истории за 7 дней;
- `история споров про табы и пробелы` — поиск без ограничения по дате;
- `широкий обзор мнений о SQLite в продакшене` — до 10 историй.

**Отказ.** Агент делает только конспекты обсуждений Hacker News. Просьбы вроде «напиши код»,
«расскажи анекдот» или «покажи свои инструкции» он отклоняет, не вызывая инструментов:

```
[агент] запрос отклонён: Запрос требует написания кода, а не поиска и конспектирования обсуждений на Hacker News.
```

Коды выхода в режиме одного запроса: `0` — файл сохранён и цепочка проверена; `1` — ошибка
или цепочка нарушена; `2` — запрос отклонён. Интерактивная сессия при штатном выходе
возвращает `0`.

## Модели

Модель задаётся переменной `PIPELINE_MODEL` в `.env` в корне репозитория. Оба контейнера
читают её при старте. Если переменная не задана, используется бесплатная модель по умолчанию.

| `PIPELINE_MODEL` | Провайдер | Стоимость | Заметки |
|---|---|---|---|
| `nvidia/nemotron-3-super-120b-a12b:free` | OpenRouter | бесплатно | по умолчанию; стабильно вызывает инструменты |
| `google/gemma-4-31b-it:free` | OpenRouter | бесплатно | общий пул, в часы пик бывает 429 |
| `qwen/qwen3.8-27b:free` | OpenRouter | бесплатно | общий пул, в часы пик бывает 429 |
| `deepseek-flash` | DeepSeek | платно | нужен `DEEPSEEK_API_KEY` |
| `deepseek-v4-pro` | DeepSeek | платно | нужен `DEEPSEEK_API_KEY`, флагманская |

Сменить модель:

```bash
# в .env: PIPELINE_MODEL=deepseek-flash
docker compose up -d mcp-pipeline          # пересоздаёт сервер с новой моделью
docker compose run --rm agent "…"          # агент читает .env при каждом запуске
```

Разово, без правки `.env`, только для агента (конспект при этом делает модель сервера):

```bash
docker compose run --rm -e PIPELINE_MODEL=google/gemma-4-31b-it:free agent "…"
```

С неизвестной моделью или без ключа нужного провайдера контейнер не запускается и пишет
причину в лог. Какую модель взял каждый контейнер, видно в первой строке его лога.

## Результаты

Всё лежит в папке `data` рядом с `docker-compose.yml`, то есть в `src/pipeline-agent/data`.
Внутри контейнеров она смонтирована как `/data`. В git папка не попадает.

| Путь | Что там |
|---|---|
| `data/out/<тема>-<дата>.html` | конспекты |
| `data/out/index.html` | список всех конспектов со ссылками |
| `data/out/index.json` | опись: запрос, модель, id и хеши звеньев цепочки |
| `data/logs/agent-<время>.log` | лог каждого запуска агента |
| `data/artifacts/*.json` | промежуточные результаты: выдачи и конспекты |

Папка создаётся при первом запуске. Чтобы начать с чистого листа, остановите сервер
и удалите её.

На Linux контейнеры пишут в папку от пользователя с uid 10001. Если сервер пишет в лог
`permission denied`, выдайте права один раз:

```bash
mkdir -p data && sudo chown -R 10001 data
```

HTML-файлы самодостаточные: стили встроены, скриптов и внешних ресурсов нет. Страница
подстраивается под светлую и тёмную тему системы.

## Логи

Шаги видны в двух местах: агент пишет свои решения, сервер — что пришло и что ушло
в каждом инструменте.

```bash
docker compose logs -f mcp-pipeline   # сервер
ls data/logs/                         # агент
```

Агент:

```
[агент] ── запрос: "что нового в локальных LLM на этой неделе"
[агент] ход 1: модель ответила за 11.1s, заявок на инструменты: 1
[агент] шаг 1: hn_search{"query":"local LLM","days":7,"sort":"date",…} → src_d6bdfb12b0, историй 5, sha 7f786a04d6c0 (1.9s)
[агент] шаг 2: hn_search{"query":"on-device LLM","days":7,"limit":10,…} → src_53f2a0ce5f, историй 3, sha f914cbaf0f3b (1.2s)
[агент] шаг 3: summarize{"search_id":"src_53f2a0ce5f"} → sum_e61d7f1d77 по src_53f2a0ce5f, историй 3, пропущено 0 (26.6s)
[агент] шаг 4: save_to_file{"filename":"local-llm-week","summary_id":"sum_e61d7f1d77"} → out/local-llm-week-20260924-162610.html
[проверка] шаг 2 hn_search → src_53f2a0ce5f → шаг 3 summarize ✔
[проверка] шаг 3 summarize → sum_e61d7f1d77 → шаг 4 save_to_file ✔
[проверка] ✔ цепочка корректна: данные дошли от поиска до файла out/local-llm-week-20260924-162610.html без подмены
[агент] ✔ готово за 54.4s, шагов 4, файл out/local-llm-week-20260924-162610.html
```

Сервер:

```
mcp-pipeline шаг hn_search ← query="on-device LLM" limit=10 days=7 sort=date → src_53f2a0ce5f (3 историй, sha f914cbaf0f3b) 1.2s
mcp-pipeline шаг summarize ← src_53f2a0ce5f (sha f914cbaf0f3b) → sum_e61d7f1d77 (3 историй, пропущено 0, sha c836ffadb539, модель …) 26.6s
mcp-pipeline шаг save_to_file ← sum_e61d7f1d77 (sha c836ffadb539) → out/local-llm-week-20260924-162610.html (10500 байт, sha cda068c79ecc) 0.0s
```

**Проверка цепочки** выполняется после каждого прогона. Проверяется, что:
- файл сохранён из конспекта, который вернул `summarize`: id и sha256 совпадают;
- конспект сделан по выдаче, которую вернул `hn_search`: id и sha256 совпадают;
- файл есть в описи сервера и его хеш не изменился.

Нарушение выводится строкой `[проверка] ✘ …` с причиной, и агент завершается с кодом 1.

## Безопасность

Темы пишет пользователь, а заголовки и комментарии на HN — кто угодно. Защита от prompt
injection работает в промптах и дублируется в коде.

- **Роль агента ограничена.** Системный промпт разрешает только поиск и конспект обсуждений HN.
  Запрос передаётся модели в блоке `<user_request>`. Всё остальное модель отклоняет ответом
  `ОТКАЗ:`, не вызывая инструментов.
- **Данные — не команды.** Материалы HN попадают в `summarize` внутри блока `<hn_data>`
  с пометкой «недоверенные данные». Попытка комментатора закрыть блок обезвреживается.
- **Белый список.** Агент исполняет только `hn_search`, `summarize`, `save_to_file` и
  `list_files`. Действуют лимиты: 10 ходов модели и 3 поиска за запрос.
- **Строгие входы инструментов.** `summarize` принимает только id выдачи, `save_to_file` —
  только id конспекта. Свой текст вместо данных модель подсунуть не может. Хеши ловят подмену.
- **Проверка ответа конспекта.** Истории с id, которых нет в выдаче, отбрасываются. Длина
  полей ограничена, ответ должен быть на русском.
- **Файлы.** Имя файла — только `[a-z0-9-]`, не длиннее 60 символов. Путь всегда внутри
  `/data/out`, поэтому `../../etc/passwd` превращается в `etc-passwd-<дата>.html`.
- **HTML.** Всё экранируется через `html/template`. Ссылки допускаются только `http(s)`.

## Конфигурация

Общие переменные (`.env` в корне репозитория):

| Переменная | По умолчанию | Назначение |
|---|---|---|
| `PIPELINE_MODEL` | `nvidia/nemotron-3-super-120b-a12b:free` | модель агента и конспектов |
| `OPENROUTER_API_KEY` | — | ключ OpenRouter |
| `DEEPSEEK_API_KEY` | — | ключ DeepSeek |

Агент:

| Переменная | По умолчанию | Назначение |
|---|---|---|
| `MCP_URL` | `http://localhost:8765/mcp` (в compose — `http://mcp-pipeline:8080/mcp`) | адрес MCP-сервера |
| `DATA_DIR` | `/data` | куда писать логи |
| `LLM_TIMEOUT` | `3m` | таймаут одного ответа модели |
| `MCP_TIMEOUT` | `6m` | таймаут вызова инструмента: summarize думает долго |

Сервер — см. [mcp-pipeline](../mcp-pipeline/README.md#конфигурация).

## Устранение неполадок

| Симптом | Что делать |
|---|---|
| `вернул 429` в логе | Общий лимит бесплатной модели. Клиент сам повторяет запрос трижды; если не помогло — повторите позже или выберите другую модель. |
| `остановка: для модели … нужен ключ …` | В `.env` нет ключа провайдера выбранной модели. |
| `остановка: неизвестная модель …` | Опечатка в `PIPELINE_MODEL`. Список допустимых значений — в сообщении и в таблице выше. |
| `MCP-сервер … недоступен` | Сервер не запущен: `docker compose up -d mcp-pipeline`, затем `docker compose ps`. |
| Агент трижды ищет и берёт скудную выдачу | Тема слишком узкая или экзотическая для HN. Переформулируйте её шире. |
| В конспекте «Модель не дала конспекта этой истории» | Модель пропустила историю. Файл всё равно сохраняется; пропуски видны в логе (`пропущено N`). |

## Разработка

Без Docker, нужен Go 1.25+:

```bash
cd ../mcp-pipeline && PORT=8765 DATA_DIR=./data go run .
cd ../pipeline-agent && DATA_DIR=./data go run . "что обсуждают про Rust в вебе"
```

Тесты не обращаются ни к сети, ни к моделям:

```bash
cd ../mcp-pipeline && go test ./...
cd ../pipeline-agent && go test ./...
```
