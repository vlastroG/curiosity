# Doc Index

Сервис строит поисковый индекс по книгам: режет текст на чанки, считает для каждого чанка
эмбеддинг локальной моделью на видеокарте и складывает всё в SQLite вместе с метаданными.
Веб-интерфейс ищет по смыслу: вопрос можно задать по-русски, книгу указывать не нужно.
Каждое найденное место открывается в читалке с подсветкой.

Индекс строится в четырёх вариантах, чтобы их можно было сравнить: три способа нарезки
и две модели. Вкладка «Сравнение» считает метрики вариантов по контрольным вопросам.

По умолчанию индексируются два романа Марка Твена с [Project Gutenberg](https://www.gutenberg.org):
*The Adventures of Tom Sawyer* ([#74](https://www.gutenberg.org/ebooks/74)) и
*Adventures of Huckleberry Finn* ([#76](https://www.gutenberg.org/ebooks/76)). Вместе это около
миллиона символов, почти 600 страниц.

## Как это работает

```
 для каждой книги: зеркало Gutenberg (один раз) ─► data/sources/pgN.txt
   ─► очистка: шапка, лицензия, оглавление ─► главы (+ описания из оглавления), абзацы
   ─► нарезка ─┬─ fixed ─────────────┐
               ├─ structure ─────────┼─► bge-m3 (Ollama, GPU) ─┐
               ├─ semantic ──────────┘                         ├─► L2-норма ─► SQLite data/index.db
               └─ structure·nomic ─────► nomic-embed-text ─────┘   (один индекс на все книги)

 браузер ── вопрос ──► doc-index ── вектор вопроса ──► Ollama
                          └─ сравнение со всеми чанками всех книг ─► top-5 по каждому варианту
                                 └─ «Открыть в книге» ─► читалка: глава, найденный чанк подсвечен
```

Контейнеров два, они в одной сети compose:

- **ollama** — официальный образ [Ollama](https://ollama.com), держит модели эмбеддингов
  и считает на видеокарте. Веса моделей лежат в томе `ollama-models` и скачиваются один раз.
  Наружу порт не открыт.
- **doc-index** — Go-сервер: интерфейс и API на порту 5180, индексация, поиск. К модели обращается
  по `http://ollama:11434`. Индекс и тексты книг лежат в `./data` рядом с `docker-compose.yml`.

В интернет сервис ходит дважды и только при первой индексации: за моделями (registry.ollama.ai)
и за текстами книг (зеркало Gutenberg). Тексты и векторы машину не покидают.

## Четыре варианта индекса

| Вариант | Как режет | Модель | Что показывает |
|---|---|---|---|
| **fixed** — фиксированный размер | окно 800 токенов с перекрытием 80, граница по пробелу | bge-m3 | базовая точка: чанк может начаться посреди предложения и захватить две главы |
| **structure** — по структуре | главы не пересекает, внутри главы — по абзацам; длинный абзац — по предложениям | bge-m3 | что даёт структура документа |
| **semantic** — по смыслу | режет там, где соседние предложения меньше всего похожи по эмбеддингам | bge-m3 | эмбеддинги работают и для нарезки; совпадают ли найденные ими границы с главами |
| **structure·nomic** | как structure | nomic-embed-text | роль модели: чанки те же, но модель понимает только английский |

Общие параметры: чанк 500–1000 токенов, перекрытие 80 токенов (от 50 до 100). Перекрытие —
хвост предыдущего чанка в начале следующего. У structure и semantic оно начинается с начала
предложения, если с него набирается 50–100 токенов. Если последнее предложение длиннее,
перекрытие режется по слову ровно на 80 токенов: такие чанки видны в метрике «начинаются
посреди предложения».

**semantic подробнее.** Текст делится на предложения. Для каждого предложения считается эмбеддинг
окна «предложение ± соседнее». Одиночное «No answer.» слишком короткое, чтобы судить по нему
о теме. Между соседними окнами считается расстояние 1 − cos. Среди всех мест, где тело чанка
укладывается в 420–920 токенов (500–1000 вместе с перекрытием), выбирается место с наибольшим
расстоянием. Заголовки глав в окна не попадают, так что главы стратегия правда не видит.

**Текст для эмбеддинга.** У structure перед текстом чанка стоит строка «книга — глава с описанием»,
у fixed и semantic — только название книги: глав они не знают. У `nomic-embed-text` к тексту
добавляются префиксы `search_document:` и `search_query:`, на которых модель обучалась.

## Метаданные чанка

| Поле | Пример |
|---|---|
| `chunk_id` | `structure-tom-0012` — вариант, книга, номер; при тех же тексте и параметрах не меняется |
| `source` | `gutenberg:74` |
| `title`, `author` | `The Adventures of Tom Sawyer`, `Mark Twain` |
| `section` | `Chapter II. Strong Temptations—Strategic Movements—The Innocents Beguiled`; если чанк захватил несколько глав — `Chapter I → Chapter II` |
| `sections` | номера всех захваченных глав |
| `start`, `body_start`, `end` | байты в очищенном тексте книги; `[start, body_start)` — перекрытие с предыдущим чанком |
| `tokens` | размер в токенах |
| `fingerprint` | отпечаток варианта книги (см. «Повторный запуск») |
| `vector` | эмбеддинг, float32, длина 1 |

## Нормализация векторов

Каждый вектор приводится к единичной длине (L2). Тогда косинусное сходство двух векторов — это
просто их скалярное произведение, и векторы всех чанков сравнимы между собой. Косинус лежит
от −1 до 1, в интерфейсе он показан в диапазоне 0–1 как (1 + cos) / 2.

Каждую координату вектора в 0–1 не масштабируем (min-max). Такое масштабирование
меняет углы между векторами и портит поиск.

## Требования

- Docker с Compose v2.
- Видеокарта. Эмбеддинги считаются **только на GPU**: если модель не поместилась в видеопамять
  целиком, индексация и поиск останавливаются с понятной ошибкой. Проверка — по
  `size_vram` в `/api/ps` Ollama после загрузки модели.

| Машина | Что нужно |
|---|---|
| Windows 10/11, NVIDIA | Docker Desktop на WSL2, свежий драйвер NVIDIA. `docker compose up -d` |
| Linux, NVIDIA | [NVIDIA Container Toolkit](https://docs.nvidia.com/datacenter/cloud-native/container-toolkit/). `docker compose up -d` |
| Linux, AMD | ROCm: `docker compose -f docker-compose.yml -f docker-compose.amd.yml up -d` |
| macOS, Apple Silicon | Docker на Mac не передаёт видеокарту в контейнеры. Поставьте [Ollama](https://ollama.com/download) приложением (считает на Metal) и запустите `docker compose -f docker-compose.yml -f docker-compose.mac.yml up -d` |

Проверено на Windows 11 + RTX 3060 Ti. Остальные строки таблицы написаны по документации
Ollama и Docker.

Модели занимают около 1,5 ГБ на диске и 1,5 ГБ видеопамяти.

## Интерфейс

- **Поиск.** Поле вопроса, под ним примеры из контрольных вопросов. Можно включить до трёх
  вариантов индекса одновременно, у каждого своя колонка. В колонке пять найденных мест:
  - сходство;
  - книга и глава;
  - фрагмент;
  - отметки «захватывает две главы» и «обрывается посреди предложения».

  Одна и та же глава во всех колонках одного цвета. У вопроса из примеров правильная
  глава известна: карточки из неё отмечены ✔, а в заголовке колонки написано, на каком
  месте она нашлась. Фильтр «Где искать» сужает поиск до одной книги, по умолчанию ищет
  по всем.
- **Книга.** Читалка по локальной копии. «Открыть в книге» ведёт к главе с найденным местом,
  прокручивает к нему и подсвечивает чанк. Перекрытие с предыдущим чанком подсвечено бледнее.
  «Показать нарезку» размечает главу чанками выбранного варианта: видно, где fixed режет
  посреди фразы, а semantic — на смене сцены.
- **Сравнение.** Сводит варианты в одну таблицу метрик и показывает гистограммы размеров
  чанков, совпадение разрезов semantic с главами и таблицу контрольных вопросов. Вверху —
  вывод, собранный из этих цифр.
- **Индекс.** Здесь запускается индексация, её этапы идут вживую. Для каждого варианта
  видно число чанков, токенов, размерность и время. Отдельно показаны состояние Ollama
  и видеокарты и пример одного чанка со всеми метаданными и началом вектора.

## Сравнение вариантов

| Метрика | Что значит |
|---|---|
| hit@1, hit@3, hit@5 | доля вопросов, где нужная глава нашлась на первом месте, в тройке, в пятёрке |
| MRR@10 | среднее 1/место нужной главы (0, если её нет в первой десятке) |
| книга на 1-м месте | первое место — из правильной книги; книгу в вопросе не указывали |
| hit@1 по-русски / по-английски | отдельно для вопросов на языке книги и на русском |
| в диапазоне 500–1000 | доля чанков рекомендованного размера |
| перекрытие | сколько токенов проиндексировано повторно |
| захватывают две главы, обрываются посреди предложения | целостность чанков |

Место засчитывается, если чанк из правильной книги и захватывает одну из ожидаемых глав.

### Контрольные вопросы

Лежат в [`eval/questions.json`](eval/questions.json). На индекс вопросы не влияют: после правки
файла сравнение пересчитывается за секунды, переиндексация не нужна. Каталог `eval` смонтирован
в контейнер, пересобирать образ тоже не нужно.

```json
{"id": "tom-fence", "lang": "ru", "book": "tom", "chapters": ["II"], "evidence": ["whitewash", "apple"],
 "q": "Как Том заставил друзей красить забор вместо себя?"}
```

`evidence` — слова, которые обязаны быть в указанной главе. Так файл проверяет сам себя:
если глава указана неверно, вопрос помечается «ответ не подтверждён текстом» и в метрики
не идёт. Такие вопросы перечислены под таблицей на вкладке «Сравнение».

## Модели

Задаются в общем `.env` в корне репозитория и читаются при старте контейнера.

| Переменная | По умолчанию | Допустимо |
|---|---|---|
| `EMBED_MODEL` | `bge-m3` | `bge-m3` — многоязычная, контекст 8K, вектор 1024; `qwen3-embedding:0.6b` — многоязычная, вектор 1024 |
| `COMPARE_MODEL` | `nomic-embed-text` | `nomic-embed-text` — английская, вектор 768; пусто — без четвёртого варианта |

Сменили модель — у вариантов поменяется отпечаток, и следующая индексация их пересчитает.

## Повторный запуск

- **Перезапуск контейнеров** (`docker compose restart`, `down` и `up`) ничего не пересчитывает.
  Индекс и книги лежат в `./data`, модели — в томе `ollama-models`. Интерфейс сразу готов к поиску.
- **Повторная индексация** сверяет отпечатки. Отпечаток — sha256 текста книги, параметры нарезки,
  модель, калибровка токенов и формат текста для эмбеддинга. Если ничего не изменилось, вариант
  получает статус «без изменений» за доли секунды. Если изменилось, пересчитывается только
  затронутый вариант.
- **Прерванная индексация** продолжается с места остановки: записанные пачки остаются в индексе.
- **«Построить заново»** (`index --rebuild`) стирает индекс и считает всё с нуля. Скачанные книги
  и модели при этом остаются.
- `docker compose down -v` удаляет том с моделями, при следующей индексации они скачаются снова.
  Удаление `./data` стирает индекс и книги.

## Токены

Токенизатор модели скрыт внутри Ollama, но Ollama сообщает, сколько токенов было во входе
(`prompt_eval_count`). Перед первой индексацией 30 образцов по ~2000 символов отправляются
в модель по одному. По ответам считается, сколько символов приходит в среднем на токен,
и по этому коэффициенту режутся чанки. Калибровка сохраняется в индексе. В конце индексации
в лог пишется сверка: сколько токенов насчитала оценка и сколько — модель.

## Книги и правила Project Gutenberg

- Тексты — общественное достояние: Твен умер в 1910 году.
- Автоматические запросы к www.gutenberg.org запрещены, для программ предназначены зеркала.
  Поэтому книга скачивается один раз с зеркала (`GUTENBERG_MIRROR`), с паузой между
  запросами, и кэшируется в `data/sources`.
- Без сети файл можно положить туда руками: `data/sources/pg74.txt`.
- Служебная шапка и лицензия Gutenberg вырезаются, в индекс и читалку попадает только
  текст романа.
- Ссылки на конкретные места ведут в собственную читалку по локальной копии: так правила
  Gutenberg и просят. Рядом ссылка на страницу книги на gutenberg.org.
- Другие книги: номера через запятую в `BOOKS` (например, `BOOKS=74,76,1342`). Лучше всего
  разбираются книги с заголовками `CHAPTER I` и т. п.

## Данные

```
data/
├── index.db            SQLite: книги, чанки с метаданными и векторами, состояние вариантов
└── sources/pg74.txt    исходные файлы книг
```

Таблицы: `books` (очищенный текст и разметка), `chunks` (метаданные, текст, вектор BLOB),
`variants` (готовность и статистика каждого варианта для каждой книги), `meta` (калибровка,
версия индекса). Поиск — полный перебор векторов в памяти. На несколько тысяч чанков это
миллисекунды, отдельный векторный движок не нужен.

## Устранение неполадок

| Симптом | Причина и что делать |
|---|---|
| «Ollama считает … на процессоре» | контейнер не видит видеокарту. Проверьте `docker compose exec ollama nvidia-smi`, обновите драйвер и Docker Desktop |
| «поместилась в видеопамять только на N%» | видеопамять занята другими программами. Освободите её и повторите |
| «Ollama недоступна» | контейнер `ollama` не запущен или ещё стартует: `docker compose ps`, `docker compose logs ollama` |
| «книга N не скачалась» | зеркало недоступно. Смените `GUTENBERG_MIRROR` или положите файл в `data/sources/pgN.txt` |
| поиск отвечает «индекс не построен» | вкладка «Индекс» → «Построить индекс» |

## Разработка

```bash
# бэкенд
cd backend
go test ./...
OLLAMA_URL=http://localhost:11434 DATA_DIR=../data EVAL_FILE=../eval/questions.json go run ./cmd/docindex serve

# интерфейс (прокси /api на :8080)
cd frontend
npm install
npm test
npm run dev
```

Тесты в сеть не ходят. Книга в формате Gutenberg собирается синтетически, Ollama подменяется
сервером на `httptest`. Его эмбеддинги — «мешок слов» по хешу, этого хватает, чтобы проверить
поиск, сравнение и все отказы: модель на процессоре, сбой посреди индексации, неверные вопросы.
