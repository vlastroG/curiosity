# Thought Forge

Неделя 1, день 3 — разные способы рассуждения.

Одна и та же задача решается через API четырьмя способами. Способ задаётся только
system prompt'ом и числом вызовов модели: сам вопрос пользователя не меняется.
Есть две вкладки — чат с переключалкой режимов и экран сравнения, который прогоняет
один вопрос через все четыре режима сразу.

## Режимы

| Режим | Что уходит в system prompt | Вызовов |
| --- | --- | --- |
| **Прямой ответ** | ничего, system-сообщение не отправляется вовсе | 1 |
| **Пошагово** | требование разбить решение на пронумерованные шаги, выписывать промежуточные результаты, проверить решение и закончить строкой `Ответ:` | 1 |
| **Предпромпт** | вызов 1 — «ты инженер промптов, не решай задачу, составь промпт для её решения»; вызов 2 — сгенерированный текст идёт как system prompt | 2 |
| **Совет экспертов** | три ролевых промпта параллельно (аналитик, инженер, критик), затем модератор сводит мнения | 4 |

Критик в параллельной схеме не критикует чужие решения — при одновременном запуске
их ещё нет. Вместо этого он сначала перечисляет ловушки задачи, а потом решает сам,
обходя их. Расхождения между экспертами разбирает модератор на четвёртом вызове.

Промежуточные артефакты видны в интерфейсе: у «Предпромпта» раскрывается
сгенерированный промпт, у «Совета экспертов» — три отдельных мнения.

Параметры сэмплинга одинаковы для всех режимов и намеренно не выведены в интерфейс
(`temperature = 0.2`, `max_tokens = 1500`, см. `src/api.js`): разница в ответах должна
идти от способа рассуждения, а не от настроек генерации.

## Сравнение

Задача с проверяемым ответом и классической ловушкой — легко забыть длину самого поезда:

> Поезд длиной 200 метров движется с постоянной скоростью 72 км/ч и въезжает в тоннель
> длиной 1300 метров. Сколько секунд пройдёт с момента, когда локомотив въехал в тоннель,
> до момента, когда последний вагон полностью покинул тоннель?

Верный ответ — **75 с**: путь равен 1300 + 200 = 1500 м, скорость 20 м/с.
Типичная ошибка — 65 с (забыта длина поезда).

Два прогона одного и того же вопроса:

| Режим | Прогон 1 | Прогон 2 | Токены (1 / 2) | Время (1 / 2) |
| --- | --- | --- | --- | --- |
| Прямой ответ | **75** ✓ | **75** ✓ | 229 / 236 | 2.7 с / 2.8 с |
| Пошагово | **75** ✓ | **75** ✓ | 521 / 520 | 3.7 с / 3.8 с |
| Предпромпт | **150** ✗ | **75** ✓ | 914 / 1090 | 4.9 с / 6.0 с |
| Совет экспертов | **75** ✓ | **75** ✓ | 1939 / 2214 | 5.1 с / 7.2 с |

### Отличаются ли ответы

По содержанию рассуждения — сильно, по итоговому числу — почти нет. Три режима из четырёх
дали 75 в обоих прогонах. Различается форма: прямой ответ выдаёт короткий расчёт,
«Пошагово» добавляет блок «Дано / Найти» и проверку подстановкой, «Совет экспертов» —
явное сопоставление трёх решений.

### Какой способ дал наиболее точный результат

Устойчиво верны «Пошагово» и «Совет экспертов». «Прямой ответ» на этой задаче тоже не
ошибся — ловушка оказалась слишком известной, чтобы модель на ней споткнулась.

Показателен провал «Предпромпта» в первом прогоне. Сгенерированный промпт был хорошим:
он сам перечислил верный путь решения (1300 + 200 = 1500 м), назвал типичные ошибки и
описал самопроверку. Но последней строкой добавил: «Формат ответа: только число, без
единиц измерения и пояснений». На втором вызове модель выполнила это требование
буквально — посчитала без единого промежуточного шага и выдала 150. Во втором прогоне
с тем же вопросом тот же режим ответил 75.

Отсюда два вывода:

1. Модель, оптимизируя промпт, склонна ужимать формат вывода — и тем самым отбирает
   у себя же право рассуждать вслух. Ровно то, что даёт точность в режиме «Пошагово»,
   «Предпромпт» способен запретить своими руками.
2. Режим с запретом на рассуждение нестабилен: при одинаковом вопросе и `temperature = 0.2`
   он дал разные ответы в двух прогонах, тогда как режимы с развёрнутым решением
   повторяемы.

Цена тоже различается заметно: «Совет экспертов» стоит вчетверо больше вызовов и
в 8–9 раз больше токенов, чем прямой ответ, при том же итоговом числе. На задаче,
где эксперты не расходятся, эта надбавка не окупается — она полезна там, где расхождение
действительно возможно, и модератору есть что разбирать.

## Запуск

```bash
docker compose -f src/thought-forge/docker-compose.yml up --build
```

Затем http://localhost:5175

Без compose:

```bash
docker build -t thought-forge ./src/thought-forge
docker run -p 5175:80 -e DEEPSEEK_API_KEY=sk-your-key-here thought-forge
```

Ключ берётся из `.env` в корне репозитория (`DEEPSEEK_API_KEY=...`). При старте контейнера
`docker-entrypoint.sh` записывает его в `env-config.js`, откуда он попадает в `window._env_`.

## Ограничение по безопасности

Бэкенда нет: собранная статика отдаётся nginx, а запросы к DeepSeek уходят прямо из браузера.
Значит, ключ виден в исходниках страницы любому, кто её откроет. Для локального учебного
приложения это приемлемо, для публичного развёртывания — нет: там нужен серверный прокси,
который держит ключ у себя.
