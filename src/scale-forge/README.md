# Scale Forge

Неделя 1, день 5 — версии моделей.

Один и тот же вопрос уходит одновременно в три модели разного класса. Каждая колонка —
самостоятельный чат со своей историей: вопросы общие, ответы у всех три разные, и дальше
диалог у каждой модели развивается по-своему. Под каждым ответом — время, токены и стоимость,
в шапке колонки — накопленный итог по всему диалогу.

## Три класса

| Класс | Модель | Провайдер | Цена за 1M токенов (вход / выход) |
| --- | --- | --- | --- |
| слабая | `liquid/lfm-2.5-2.6b:free` (2.6B параметров) | OpenRouter | бесплатно |
| средняя | `deepseek-v4-flash` | DeepSeek API | $0.08708 / $0.17416 |
| сильная | `deepseek-v4-pro` | DeepSeek API | $1.039302 / $2.078604 |

Цены взяты из каталога OpenRouter (`GET https://openrouter.ai/api/v1/models`) на 2026-09-04.
Оговорка: средняя и сильная модели вызываются напрямую через API DeepSeek, а прайс взят
у OpenRouter, который перепродаёт те же модели — прямые цены DeepSeek могут отличаться.
Для задания это некритично: между классами разница в десятки раз, и её видно в любом случае.
Все цены лежат в одном месте — `src/models.js`, там же меняется набор моделей.

`temperature = 0.3` и общий system prompt на формат одинаковы для всех трёх — день 5 сравнивает
модели, а не настройки сэмплинга (это была тема дня 4) и не способ промптинга (день 3).

## Что показывается

Под каждым ответом:

- **время** — от отправки запроса до получения ответа, замеряется в браузере;
- **токены** — `prompt_tokens → completion_tokens` из `usage` ответа API;
- **токены на рассуждение** — у рассуждающих моделей (обе DeepSeek V4) часть
  `completion_tokens` уходит во внутреннее рассуждение и не попадает в видимый текст;
  берётся из `usage.completion_tokens_details.reasoning_tokens`;
- **стоимость** — `prompt_tokens × цена входа + completion_tokens × цена выхода`.

В шапке колонки — сумма токенов, сумма стоимости и среднее время ответа за весь диалог.

## Ключи

Нужны два ключа в `.env` в корне репозитория (образец — `.env.example`):

```
DEEPSEEK_API_KEY=sk-...
OPENROUTER_API_KEY=sk-or-v1-...
```

Ключ OpenRouter берётся на https://openrouter.ai/keys. Если слабая модель отвечает ошибкой
вроде «No endpoints found matching your data policy», нужно в настройках приватности OpenRouter
разрешить бесплатных провайдеров — у бесплатных моделей это обязательное условие.

Другие бесплатные модели, если эта окажется недоступна (список можно получить тем же запросом
`GET https://openrouter.ai/api/v1/models` и отфильтровать по суффиксу `:free`):
`poolside/laguna-xs-2.1:free`, `google/gemma-4-26b-a4b-it:free`, `liquid/lfm-2.5-2.6b:free`.
Меняется одной строкой в `src/models.js`.

## Запуск

```bash
docker compose -f src/scale-forge/docker-compose.yml up --build
```

Затем http://localhost:5178

Без compose:

```bash
docker build -t scale-forge ./src/scale-forge
docker run -p 5178:80 -e DEEPSEEK_API_KEY=sk-... -e OPENROUTER_API_KEY=sk-or-v1-... scale-forge
```

При старте контейнера `docker-entrypoint.sh` записывает оба ключа в `env-config.js`,
откуда они попадают в `window._env_`.

## Ограничение по безопасности

Бэкенда нет: собранная статика отдаётся nginx, а запросы к DeepSeek и OpenRouter уходят прямо
из браузера. Значит, оба ключа видны в исходниках страницы любому, кто её откроет. Для локального
учебного приложения это приемлемо, для публичного развёртывания — нет: там нужен серверный
прокси, который держит ключи у себя.
