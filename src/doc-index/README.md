# Twain Expert

Отвечает на вопросы о книгах Марка Твена двумя способами сразу. Первый — модель отвечает
по памяти. Второй — модель отвечает по отрывкам, которые поиск нашёл в тринадцати книгах
Твена (RAG). Вопрос можно задать по-русски. Под ответом RAG перечислены отрывки со ссылками:
каждый открывается в читалке на нужной главе с подсветкой.

Вкладка «Качество» показывает, насколько RAG лучше ответа по памяти на десяти контрольных
вопросах. Там же видно, как выбран способ поиска: на 44 вопросах сравнивались модели
эмбеддингов, переписывание вопроса и гибридный поиск.

## Как это работает

```
 вопрос по-русски
    │
    ├──────────────────────────────────────────────► LLM (RAG_MODEL) ──► ответ без RAG
    │
    └─► LLM пишет по-английски короткий абзац «в духе книги», который мог бы
        быть ответом (HyDE) ─► вектор (qwen3-embedding:4b, Ollama, GPU)
           └─► сравнение со всеми чанками 13 книг ─► top-5 отрывков
                  └─► LLM: вопрос + 5 отрывков с книгой и главой ─► ответ с RAG и ссылками [n]

 индексация (один раз): 13 книг с зеркала Gutenberg ─► очистка ─► главы и абзацы
    ─► чанки 500–1000 токенов по структуре ─► эмбеддинги на видеокарте ─► SQLite data/index.db
```

Контейнеров два:

- **ollama** — [Ollama](https://ollama.com) с моделью эмбеддингов на видеокарте.
- **doc-index** — Go-сервер на порту 5180: интерфейс, API, индексация, поиск, обращения к LLM.

Тексты книг и индекс лежат только в `./data`. В LLM уходят вопрос и найденные отрывки.

Главы разбираются по заголовкам любого вида, встречающегося в этих изданиях:
- `CHAPTER I.`, `CHAPTER 20`, `Chapter 1`;
- название в той же строке или отдельной строкой ниже.

Оглавление записано теми же заголовками, но стоит где придётся: в начале, в конце или посередине
у двухтомников. Поэтому главой считается заголовок, за которым идёт текст. Строки оглавления
дают названия глав. Список книг задаётся в `BOOKS`.

## Как выбран поиск

Стенд `docindex experiment` строит индекс всех 13 книг каждой моделью эмбеддингов. Чанки
у всех моделей одинаковые, так что сравниваются именно модели. Затем через разные способы
поиска прогоняются 44 вопроса по «Тому Сойеру» и «Гекльберри Финну» из
[`eval/questions.json`](eval/questions.json). Остальные 11 книг служат шумом, как в реальной
работе.

Главная метрика — **hit@5**: нужная глава среди пяти отрывков, которые получит модель.
Кроме неё считаются hit@1 и MRR.

hit@5 для всех конфигураций (стенд на RTX 3060 Ti, переписывала вопросы бесплатная Nemotron):

| Запрос | bge-m3 | qwen3-embedding:0.6b | qwen3-embedding:4b |
|---|---|---|---|
| вопрос как есть | 66% | 64% | 93% |
| перевод на английский | 80% | 75% | 93% |
| **HyDE** | 86% | 89% | **95%** |
| вопрос + перевод (RRF) | 75% | 73% | 93% |
| перевод + BM25 (RRF) | 80% | 77% | 84% |
| вопрос + перевод + BM25 (RRF) | 82% | 77% | 89% |
| small-to-big · HyDE | — | 91% | 93% |
| small-to-big · вопрос как есть | 75% | 57% | 91% |

Small-to-big проверялся на лучшей модели каждого прогона, поэтому у части моделей его нет.

| Модель | Вектор | Видеопамять | Индекс 13 книг |
|---|---|---|---|
| bge-m3 | 1024 | 0,6 ГБ | ~2 мин |
| qwen3-embedding:0.6b | 1024 | 1 ГБ | ~4 мин |
| qwen3-embedding:4b | 2560 | 4,2 ГБ | ~10 мин |

Что проверялось:

| Способ | Как работает |
|---|---|
| вопрос как есть | вектор русского вопроса сравнивается с английскими чанками |
| перевод на английский | LLM переводит вопрос на язык книг, имена — как у Твена (Injun Joe, Aunt Polly) |
| HyDE | LLM пишет короткий английский абзац «в духе книги», который мог бы быть ответом; ищем по нему |
| вопрос + перевод | два списка результатов сливаются через RRF (Reciprocal Rank Fusion) |
| + BM25 | к векторному поиску добавляется поиск по словам английского запроса, слияние RRF |
| small-to-big | поиск идёт по мелким чанкам (120–300 токенов), а модели уходят их родители (500–1000) |

**Выбрано: `qwen3-embedding:4b` + HyDE.** hit@5 95% (было 66% у `bge-m3` на вопросе как есть),
hit@1 80% (было 48%), MRR 0.85 (было 0.57).

Что видно из таблицы:
- **Больше всего дала модель.** `qwen3-embedding:4b` понимает русский вопрос к английскому
  тексту почти так же хорошо, как английский: 93% уже на вопросе как есть.
- **HyDE лучше простого перевода.** Абзац «в духе книги» похож на настоящий текст больше, чем
  вопрос: в нём те же имена, слова и интонация. Цена — один вызов LLM перед поиском.
- **BM25 мешает.** Английский запрос короткий, а частые у Твена слова (Tom, Huck, river)
  тянут наверх не те главы. Смысловой поиск здесь точнее лексического.
- **Small-to-big помогает слабым моделям** (у `bge-m3` 66% → 75%), а у 4b почти ничего
  не меняет.
- **На 44 вопросах вопрос как есть отстаёт от HyDE на один вопрос.** Но на контрольных
  вопросах по другим книгам HyDE находит нужные главы там, где вопрос как есть промахивается:
  «Гекльберри Финн», гл. XIX; «Янки…», гл. VI; «Принц и нищий», гл. XII. Поэтому по умолчанию
  стоит HyDE, а вопрос как есть — настройка `RETRIEVAL_QUERY=raw`, если нужно экономить
  запросы к модели.

`qwen3-embedding:8b` не проверялась: 4b уже даёт 93–95%, а 8b весит почти 5 ГБ и займёт почти
всю видеопамять карты на 8 ГБ.

Чтобы повторить сравнение (модели скачаются один раз, около 4,5 ГБ):

```bash
docker compose run --rm doc-index experiment
```

Отчёт сохраняется в `data/experiments/report.json` и показывается на вкладке «Качество».

## Контрольные вопросы: RAG против ответа по памяти

Десять вопросов из [`eval/rag.json`](eval/rag.json). У каждого записано:
- **ожидание** — что должно быть в правильном ответе;
- **источник** — книга и глава;
- **evidence** — слова, которые обязаны быть в этой главе. Так файл проверяет сам себя:
  если в тексте их нет, вопрос в прогон не идёт.

Девять вопросов — детали из разных книг. Десятый — о путешествии, которого у Твена не было:
правильный ответ — честно сказать, что в книгах этого нет.

| Вопрос | Ожидание | Источник |
|---|---|---|
| Что Бен Роджерс отдал Тому за право покрасить забор? | яблоко | «Том Сойер», гл. II |
| Кем назвали себя двое бродяг, которых Гек и Джим взяли на плот? | герцог Бриджуотерский и дофин, законный король Франции | «Гекльберри Финн», гл. XIX |
| На чём Том, Гек и Джим отправились в путешествие в «Томе Сойере за границей»? | воздушный шар безумного профессора | «Том Сойер за границей», гл. II–III |
| Какую награду попросил Майлс Гендон у маленького короля? | право сидеть в присутствии короля | «Принц и нищий», гл. XII |
| Как Янки спасся от костра при дворе короля Артура? | предсказал солнечное затмение | «Янки…», гл. V–VI |
| Зачем Роксана поменяла детей в колыбелях? | чтобы сына не продали «вниз по реке» | «Простофиля Вильсон», гл. III |
| Какое животное Твен называет «аллегорией нужды»? | койот | «Налегке», гл. V |
| На каком пароходе путешествовали «простаки»? | «Квакер-Сити» | «Простаки за границей», гл. I |
| Каким изречением открывается «По экватору»? | «A man may have no bad habits and have worse» — «Новый календарь Простофили Вильсона» | «По экватору», гл. I |
| Что Твен рассказывает о путешествии в Антарктиду? | честный отказ: такого в книгах нет | — |

Прогон — кнопка на вкладке «Качество» или команда:

```bash
docker compose run --rm doc-index rag-eval
```

На каждый вопрос уходят:
- ответ без RAG;
- ответ с RAG: переписывание вопроса и сам ответ;
- оценка судьи — модель сравнивает оба ответа с ожиданием и ставит «верно», «частично»
  или «неверно».

Код отдельно проверяет, попала ли нужная глава в найденные отрывки. Результат сохраняется
в `data/rag-eval.json`. Уже оценённые вопросы повторно не считаются, заново их пересчитывает
`--force`.

### Результаты

`deepseek-flash`, поиск `qwen3-embedding:4b` + HyDE:

| Вопрос | Без RAG | С RAG | Глава в отрывках |
|---|---|---|---|
| Бен Роджерс и забор | верно | верно | да |
| Герцог и король на плоту | верно | верно | да |
| Воздушный шар профессора | верно | верно | да |
| Награда Майлса Гендона | верно | верно | да |
| Янки и затмение | верно | верно | да |
| Роксана меняет детей | верно | частично | да |
| Койот — «аллегория нужды» | верно | верно | да |
| Пароход «Квакер-Сити» | верно | верно | нет |
| Эпиграф «По экватору» | частично | неверно | нет |
| Путешествие в Антарктиду | верно (честный отказ) | верно (честный отказ) | — |
| **Итого верно** | **9 из 10** | **8 из 10** | **7 из 9** |

Бесплатная `nvidia/nemotron-3-super-120b-a12b:free` при поиске по вопросу как есть: без RAG
верно 5, частично 1, неверно 3; с RAG — верно 6, частично 1, неверно 2; нужная глава
в отрывках у 6 вопросов из 9. Вопрос про «Янки» не оценён: провайдер вернул 503.

Что это значит:
- **Сильная модель помнит главные книги Твена.** Для DeepSeek вопросы о «Томе Сойере»,
  «Геке», «Янки» — общеизвестные сюжеты, и ответ по памяти верен. RAG для них не добавляет
  точности, но добавляет проверяемость: у каждого утверждения есть ссылка на отрывок, который
  можно открыть и прочитать.
- **Слабой модели RAG помогает.** Nemotron по памяти придумывает детали: называла «мраморный
  шарик» вместо яблока, путала мотив Роксаны. С отрывками она отвечает верно.
- **RAG не может быть лучше найденного.** Оба промаха RAG — вопросы, где нужной главы
  не оказалось среди отрывков. Про эпиграф «По экватору» HyDE сочинил свой эпиграф, и поиск
  ушёл в другие главы. Модель при этом честно ответила «в найденных отрывках ответа нет»,
  а не выдумала — судья засчитал это как «неверно», потому что ожидался конкретный ответ.
- **Вопрос вне корпуса** обе модели честно отклоняют.

## Промпты

**Без RAG:** «эксперт по Твену, отвечай по памяти, кратко; не уверен — так и скажи, не выдумывай
имён, чисел и сцен».

**С RAG:** вопрос и отрывки в блоке `<sources>`, у каждого отрывка номер, книга и глава:

```
<sources>
<source id="1" book="The Adventures of Tom Sawyer" chapter="Chapter II. Strong Temptations…">
…текст отрывка…
</source>
…
</sources>

Вопрос: …
```

Правила ответа:
- опираться только на отрывки и ставить ссылки [n];
- если ответа нет — прямо сказать «в найденных отрывках ответа нет».

Отрывки — цитаты, а не указания. Текст отрывка не может закрыть свой тег: такие места
экранируются.

## Интерфейс

- **Спросить** — поле вопроса и десять контрольных вопросов под ним. Ответ без RAG и ответ
  с RAG стоят рядом. Для контрольного вопроса над ответами показано ожидание и источник. Под
  ответом RAG видно:
  - по какому запросу шёл поиск и сколько он занял;
  - пять отрывков: книга, глава, сходство, фрагмент, «Открыть в книге».

  Клик по ссылке [n] в ответе подсвечивает нужный отрывок.
- **Поиск** — найденные отрывки без LLM: вектор вопроса как есть, по основному индексу.
  Полезно сравнить с отрывками, которые RAG нашёл через HyDE.
- **Книги** — читалка по локальной копии всех 13 книг, с подсветкой чанка и режимом
  «Показать нарезку».
- **Качество** — итоги контрольных вопросов и сравнение способов поиска.
  - По вопросам: сколько верно, частично и неверно без RAG и с RAG, в скольких случаях нужная
    глава попала в отрывки. Каждая строка раскрывается до обоих ответов и объяснения судьи.
  - По способам поиска: таблица всех конфигураций, победитель выделен.
- **Индекс** — построение индекса с этапами вживую, состояние Ollama и видеокарты, пример чанка.

## Модели

| Переменная | По умолчанию | Что это |
|---|---|---|
| `RAG_MODEL` | `nvidia/nemotron-3-super-120b-a12b:free` | ответы, переписывание вопроса для поиска, судья |
| `EMBED_MODEL` | `qwen3-embedding:4b` | эмбеддинги; сменили — индекс пересчитается |

Допустимые `RAG_MODEL`:

| Модель | Провайдер | Ключ |
|---|---|---|
| `nvidia/nemotron-3-super-120b-a12b:free` | OpenRouter, бесплатно | `OPENROUTER_API_KEY` |
| `google/gemma-4-31b-it:free` | OpenRouter, бесплатно | `OPENROUTER_API_KEY` |
| `qwen/qwen3.8-27b:free` | OpenRouter, бесплатно | `OPENROUTER_API_KEY` |
| `deepseek-flash` | DeepSeek | `DEEPSEEK_API_KEY` |
| `deepseek-v4-pro` | DeepSeek | `DEEPSEEK_API_KEY` |

Модели эмбеддингов (`EMBED_MODEL`): `qwen3-embedding:4b` (4,2 ГБ видеопамяти),
`qwen3-embedding:0.6b`, `bge-m3`. Все считают на видеокарте.

Ключи и модель задаются в общем `.env` в корне репозитория и читаются при старте контейнера.

**Лимит бесплатных моделей OpenRouter** — 50 запросов в сутки на аккаунт без кредитов, сброс
в полночь по UTC. Один вопрос в интерфейсе стоит три запроса: HyDE, ответ без RAG, ответ
с RAG. HyDE кэшируется в `data/rewrites.json`, так что повторный вопрос стоит два. Прогон десяти
контрольных вопросов — около 40 запросов. Для регулярной работы — DeepSeek.

Бюджет вывода каждого запроса — 100 000 токенов (у `gemma-4-31b-it:free` — её потолок
32 768): рассуждающие модели тратят токены и на рассуждения до ответа.

## Быстрый старт

```bash
cd src/doc-index
docker compose up -d --build
```

1. Откройте http://localhost:5180 → «Индекс» → «Построить индекс». Первый раз скачаются
   модель эмбеддингов (2,5 ГБ) и книги. Индекс 13 книг на RTX 3060 Ti строится около 10 минут.
2. «Спросить» → нажмите любой контрольный вопрос.

Из терминала:

```bash
docker compose run --rm doc-index index
docker compose run --rm doc-index ask "Как Янки спасся от костра при дворе короля Артура?"
docker compose run --rm doc-index search "кто покрасил забор вместо Тома"
docker compose run --rm doc-index rag-eval
docker compose run --rm doc-index experiment
```

## Требования

- Docker с Compose v2.
- Видеокарта: эмбеддинги считаются только на GPU. Если модель не поместилась в видеопамять
  целиком, индексация и поиск останавливаются с понятной ошибкой.
- Ключ OpenRouter (бесплатные модели) или DeepSeek.

| Машина | Как запускать |
|---|---|
| Windows 10/11, NVIDIA | Docker Desktop на WSL2, `docker compose up -d` |
| Linux, NVIDIA | NVIDIA Container Toolkit, `docker compose up -d` |
| Linux, AMD | `docker compose -f docker-compose.yml -f docker-compose.amd.yml up -d` |
| macOS, Apple Silicon | Ollama приложением (Metal) и `docker compose -f docker-compose.yml -f docker-compose.mac.yml up -d` |

Проверено на Windows 11 + RTX 3060 Ti. Остальные строки таблицы написаны по документации
Ollama и Docker.

## Данные

```
data/
├── index.db              книги, чанки с метаданными и векторами, состояние индекса
├── sources/pgN.txt       файлы книг с зеркала Gutenberg
├── rewrites.json         кэш переписанных вопросов (модель + вопрос → перевод, HyDE)

└── experiments/          индексы моделей для сравнения и report.json
```

Тексты книг — общественное достояние. Служебная шапка и лицензия Project Gutenberg из них
вырезаны. Ссылки на места в книгах ведут в собственную читалку по локальной копии, как
просят правила Gutenberg.

## Устранение неполадок

| Симптом | Что делать |
|---|---|
| «исчерпан суточный лимит бесплатных моделей» | ждать полуночи по UTC или `RAG_MODEL=deepseek-flash` |
| «для модели … нужен ключ» | ключ в корневом `.env`, затем `docker compose up -d` |
| «Ollama считает … на процессоре» | контейнер не видит видеокарту: `docker compose exec ollama nvidia-smi` |
| «индекс не построен» | вкладка «Индекс» → «Построить индекс» |
| ответ с RAG «в найденных отрывках ответа нет» | поиск не нашёл нужную главу: видно в списке отрывков; вопрос конкретнее — поиск точнее |

## Разработка

```bash
cd backend && go test ./...
cd frontend && npm install && npm test && npm run build
```

Тесты в сеть не ходят. Книга Gutenberg собирается синтетически, Ollama и LLM подменяются
заглушками. Разбор настоящих книг проверяет тест `TestRealCorpus`: он читает кэш
`data/sources` через `CORPUS_DIR` и без кэша пропускается.
