# mcp-probe

Минимальный MCP-клиент: подключается к серверу и печатает список его инструментов.

Ничего с инструментами не делает — только рукопожатие и `tools/list`. Нужен, чтобы
увидеть, что именно умеет сервер, прежде чем к нему подключаться всерьёз.

## Запуск

```bash
docker build -t mcp-probe .
docker run --rm mcp-probe
```

Образ несёт в себе и клиент, и сервер, поэтому на машине не нужно ни Go, ни Node,
а сам запуск не ходит в сеть (`docker run --rm --network none mcp-probe` тоже работает).

Если Go 1.25+ и Node уже стоят, можно без контейнера — сервер подтянется через `npx`:

```bash
go run .
```

## Что видно

```
запускаю сервер: mcp-server-everything

соединение установлено: mcp-servers/everything 2.0.0 (протокол 2025-11-25)

инструменты (14):

  echo
    Echoes back the input string
    обязательные: message

  get-sum
    Returns the sum of two numbers
    обязательные: a, b
  ...
```

Первая строка после запуска — результат рукопожатия: имя, версия и версия протокола
приходят от сервера в ответе на `initialize`. Дальше идёт разобранный ответ
на `tools/list`: у каждого инструмента имя, описание и обязательные параметры
из его json-схемы.

Если соединение не установилось, причина уходит в stderr, а код возврата ненулевой:

```
$ docker run --rm -e MCP_SERVER_CMD=такого-сервера-нет mcp-probe
не получилось: соединение не установилось: exec: "такого-сервера-нет": executable file not found in $PATH
```

## Другой сервер

По умолчанию берётся `@modelcontextprotocol/server-everything` — официальный демо-сервер
протокола: ключей не требует и отдаёт инструменты разных видов. Любой другой задаётся
переменной окружения:

```bash
go run .                                                          # сервер по умолчанию
MCP_SERVER_CMD="npx -y @modelcontextprotocol/server-filesystem ." go run .
MCP_SERVER_CMD="npx -y @modelcontextprotocol/server-memory" go run .
```

Транспорт — stdio: клиент сам запускает сервер дочерним процессом и говорит с ним
через его stdin/stdout, без сетевого порта и без ключей.
