# Trip Planner

Составляет план поездки по дням: погода на каждый день, что посмотреть (с описаниями и ссылками),
бюджет в рублях и местной валюте. Пользователь заполняет короткую форму, обязателен только
город. План собирает агент на языковой модели: он обращается к четырём MCP-серверам и сам
выбирает, какой инструмент какого сервера вызвать и в каком порядке. Интерфейс показывает
каждый шаг, пока он идёт.

## Как это работает

```
 браузер ── форма ──► POST /api/runs ──► очередь ──► агент ──► модель (TRIP_MODEL)
    ▲                                                   │  выбирает инструмент
    └── SSE: «что происходит сейчас», шаги, проверки ◄──┤
                                                        │  маршрутизатор: префикс → сервер
          ┌──────────────────┬──────────────────┬──────┴───────────┬──────────────────┐
          ▼                  ▼                  ▼                  ▼                  │
     mcp-places         mcp-weather         mcp-money          mcp-trip               │
     find_city          trip_weather        country_currency   trip_create            │
     sights             (/mcp/travel)       convert            trip_set_budget        │
     sight_info                             budget_split       trip_add_day           │
                                                               trip_publish ──► data/out/*.html
     Open-Meteo,        Open-Meteo          ЦБ РФ              data/trips/*.json
     Википедия          Forecast/Archive
```

Типичный флоу — 15–25 вызовов на четыре сервера:

1. `places__find_city` находит координаты, страну и код страны.
2. `weather__trip_weather` получает погоду на даты поездки для этих координат: до 16 дней вперёд
   это прогноз, дальше — климатическая норма за 5 прошлых лет.
3. Если указан бюджет, цепочка такая: `money__country_currency` по коду страны, затем
   `money__convert` в местную валюту, затем `money__budget_split` на дни и людей.
4. `places__sights` ищет места рядом по тем же координатам, `places__sight_info` даёт
   описания и ссылки для тех, что пойдут в план.
5. `trip__trip_create` заводит план, `trip__trip_set_budget` записывает бюджет, `trip__trip_add_day`
   добавляет каждый день, `trip__trip_publish` публикует HTML.

Порядок не зашит в код, его выбирает модель. Код следит, чтобы решения исполнялись безопасно,
и после прогона проверяет, что флоу прошёл правильно.

### Маршрутизация

Серверы перечислены в `TRIP_SERVERS`. При старте и перед каждым прогоном агент запрашивает
у каждого сервера `tools/list` и показывает модели общий список инструментов с префиксом
сервера: `places__find_city`, `money__convert`. По префиксу маршрутизатор отправляет вызов
на нужный адрес. Одинаковые имена инструментов на разных серверах не конфликтуют.
Инструменты недоступного сервера модель не видит, а в интерфейсе он помечен как недоступный.

### Проверка флоу

После каждого прогона агент сверяет трассу вызовов:

| Проверка | Что значит |
|---|---|
| Маршрутизация | каждый вызов ушёл на сервер, которому принадлежит инструмент |
| find_city раньше зависимых шагов | погода, места, валюта и план — после поиска города |
| Порядок сборки плана | `trip_create`, затем дни и бюджет, затем `trip_publish` |
| Координаты из places дошли до weather и trip | координаты в погоде, поиске мест и плане совпадают с ответом `find_city` |
| Даты поездки одинаковые у weather и trip | даты погоды и плана — те, что в форме |
| Погода из weather дошла до плана | погода в днях плана совпадает с ответом `trip_weather` (±1°, ±5 %) |
| Один trip_id на весь план | все шаги сборки пишут в один и тот же план |
| Валюта из money дошла до плана | валюта той страны, которую вернул `find_city`, бюджет переведён и записан |
| План опубликован целиком | в плане есть все дни поездки |
| Prompt injection | попытки командовать моделью через данные не попали в план |

Результат показан в интерфейсе, строка на проверку. При нарушении у плана статус «готов с замечаниями».

## Требования

- Docker с Compose v2.
- Ключ [OpenRouter](https://openrouter.ai/keys) для бесплатных моделей или
  [DeepSeek](https://platform.deepseek.com/api_keys) для платных.

## Быстрый старт

1. В корне репозитория скопируйте `.env.example` в `.env` и впишите ключ:

   ```
   OPENROUTER_API_KEY=sk-or-v1-...
   ```

2. Запустите сервисы:

   ```bash
   docker compose up -d --build
   ```

3. Откройте http://localhost:5179, укажите город и нажмите «Составить план».

## Использование

### Форма

| Поле | Обязательно | Если не заполнить |
|---|---|---|
| Город | да | — |
| Начало и конец поездки | нет | поездка на 3 дня через неделю; без конца — на 3 дня от начала |
| Сколько человек | нет | 1 |
| Бюджет на всех и валюта (₽, $, €) | нет | план без расчёта денег |
| Интересы | нет | общий план |
| Темп | нет | спокойный: 2–3 места в день; насыщенный — 4–5 |

Поездка — не длиннее 14 дней и не раньше сегодняшнего дня, путешественников — от 1 до 10.
Уточняющих вопросов агент не задаёт. Всё, что пришлось додумать, попадает в раздел плана «Допущения».

### Ход работы

Пока план собирается, на странице видно:
- **полосу серверов**: сколько вызовов получил каждый и какой работает сейчас;
- **крупную карточку текущего действия**: «Модель выбирает следующий шаг…»,
  «Погода: узнаю погоду на даты поездки…», затем что вернулось;
- **ленту по ходам модели**. В каждом ходе — вызванные инструменты: сервер, понятное название,
  главные аргументы, короткий итог и время. «Данные» раскрывают сырые аргументы и ответ сервера.
  Вызовы одного хода стоят рядом, их модель выбрала разом;
- **предупреждения**: если в ответе сервера нашёлся текст, похожий на инструкцию для модели;
  если аргументы пришлось привести к схеме (небольшие модели присылают массивы строкой);
  если модель остановилась раньше публикации и агент напомнил ей закончить.

### План и история

Готовый план показывается на странице: погода по дням с пометкой «прогноз» или
«климатическая норма», места с описаниями и ссылками на Википедию, бюджет, допущения.
Кнопка «Открыть HTML» открывает самодостаточный файл: его можно сохранить или переслать.

Слева — история планов со статусами. Клик открывает план вместе с записанным ходом работы.
Планы собираются по одному: следующий ждёт в очереди, в истории виден его номер.
История хранится на диске и переживает перезапуск.

## Модели

Модель задаётся переменной `TRIP_MODEL` в `.env` в корне репозитория и читается при старте.
Если переменная не задана, используется бесплатная модель по умолчанию.

| `TRIP_MODEL` | Провайдер | Стоимость | Заметки |
|---|---|---|---|
| `nvidia/nemotron-3-super-120b-a12b:free` | OpenRouter | бесплатно | по умолчанию; стабильно вызывает инструменты |
| `google/gemma-4-31b-it:free` | OpenRouter | бесплатно | общий пул, в часы пик бывает 429 |
| `qwen/qwen3.8-27b:free` | OpenRouter | бесплатно | общий пул, в часы пик бывает 429 |
| `deepseek-flash` | DeepSeek | платно | нужен `DEEPSEEK_API_KEY` |
| `deepseek-v4-pro` | DeepSeek | платно | нужен `DEEPSEEK_API_KEY` |

Чтобы сменить модель, поменяйте `TRIP_MODEL` в `.env` и пересоздайте контейнер агента:

```bash
docker compose up -d trip-agent
```

С неизвестной моделью или без ключа нужного провайдера агент не запускается и пишет причину
в лог. Текущая модель указана под формой.

## Данные

Всё лежит в папке `data` рядом с `docker-compose.yml`. В git она не попадает.

| Путь | Что там |
|---|---|
| `data/runs/run_*.json` | история: форма, статус, события хода работы, проверки, план |
| `data/trips/trip_*.json` | планы, как их хранит mcp-trip |
| `data/out/*.html` | опубликованные планы; в браузере — `http://localhost:5179/plans/<файл>` |

На Linux контейнеры пишут в папку от пользователя с uid 10001. Если в логе `permission denied`:

```bash
mkdir -p data && sudo chown -R 10001 data
```

## Безопасность

Чужой текст попадает в систему двумя путями: через поля формы и через ответы серверов.
Описания мест берутся из Википедии, а её правит кто угодно.

- **Форма вместо свободного текста.** Единственное текстовое поле — город: только буквы,
  пробел, дефис, точка и апостроф, до 80 символов. Остальные поля — даты, числа и значения
  из фиксированных списков. Запрос для модели код собирает из проверенных полей в блоке `<trip_request>`.
- **Роль модели ограничена.** Системный промпт разрешает только составить план поездки.
  Результаты инструментов приходят в блоках `<tool_result trusted="false">` с указанием
  считать их данными, а не командами. Попытка «закрыть» блок изнутри обезвреживается.
- **Ограничения в коде.** Модель может вызвать только инструменты серверов из реестра.
  Лимиты: не больше 30 ходов и не больше 10 вызовов одного инструмента.
  Сервер планов проверяет каждую запись: формат `trip_id`, даты внутри поездки, длину
  текстов, ссылки только `http(s)`. Имя HTML-файла сервер строит сам.
- **Детектор.** Ответы серверов проверяются на типичные фразы инъекций («ignore previous
  instructions», «игнорируй инструкции», «system prompt»…). Находка видна в ленте, а проверка
  флоу убеждается, что текст не попал в план.
- **Вывод.** HTML-план собирается через `html/template` и отдаётся с CSP `default-src 'none'`.
  Интерфейс выводит данные только как текст.

## Устранение неполадок

| Симптом | Что делать |
|---|---|
| Сервер в полосе помечен «недоступен» | `docker compose ps`, затем `docker compose logs <сервис>` |
| `вернул 429` в статусе ошибки | исчерпан общий лимит бесплатной модели; повторите позже или выберите другую |
| `модель не закончила план за 30 ходов` | модель застряла на отказах сервера; причины видны в ленте (красные карточки) |
| План «готов с замечаниями» | посмотрите, какая проверка не прошла: в ней сказано, что расходится |
| Мест мало или они странные | в Википедии мало статей рядом с центром города; попробуйте интересы или другой город |

## Разработка

Нужны Go 1.25+ и Node 22+. Серверы запускаются на портах по умолчанию из `TRIP_SERVERS`:

```bash
cd ../mcp-places && PORT=8781 go run .
cd ../mcp-weather && PORT=8782 go run .
cd ../mcp-money && PORT=8783 go run .
cd ../mcp-trip && PORT=8784 DATA_DIR=../trip-agent/data go run .
cd backend && PORT=8790 DATA_DIR=../data go run ./cmd/server
cd frontend && npm install && npm run dev      # http://localhost:5178
```

Тесты не ходят ни в сеть, ни к модели:

```bash
cd backend && go test ./...
cd frontend && npm test && npm run build
```

В тестах агента модель проходит сценарии: полный флоу, отказ, инъекцию в данных, чужие
координаты, другую валюту, чужой `trip_id`. Реестр проверяется настоящими MCP-серверами по HTTP.
