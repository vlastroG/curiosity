# mcp-weather

MCP-сервер, который отдаёт погоду в месте работ. Обёртка вокруг [Open-Meteo](https://open-meteo.com):
ни ключа, ни регистрации, ни квоты.

Написан под [Agent Sprout](../agent-sprout): помощнику строителя нужны фактические
условия на объекте, чтобы не спрашивать о них человека и учесть их в плане работ.
Но сервер самостоятельный — подключить его можно к любому MCP-клиенту.

## Запуск

```bash
docker build -t mcp-weather .
docker run --rm -p 8765:8080 mcp-weather
```

Без контейнера, если есть Go 1.25+:

```bash
PORT=8765 go run .
```

Транспорт — Streamable HTTP: сервер слушает порт, клиент шлёт `POST /mcp`. Сессий нет,
ответ приходит обычным `application/json` вместо потока событий, поэтому любой вызов
воспроизводится одним `curl`.

## Что видно

Сначала инструменты — это `tools/list`:

```bash
curl -s -X POST http://localhost:8765/mcp \
  -H 'Content-Type: application/json' \
  -H 'Accept: application/json, text/event-stream' \
  -H 'MCP-Protocol-Version: 2025-11-25' \
  -d '{"jsonrpc":"2.0","id":1,"method":"tools/list"}'
```

```json
{"jsonrpc":"2.0","id":1,"result":{"tools":[
  {"name":"find_place",
   "description":"Найти населённый пункт по названию: координаты, страна, регион, часовой пояс…",
   "inputSchema":{"type":"object",
     "properties":{
       "name":{"type":"string","description":"название населённого пункта, например «Москва»…"},
       "limit":{"type":"integer","description":"сколько вариантов вернуть, от 1 до 10; по умолчанию 5"}},
     "required":["name"],"additionalProperties":false}},
  {"name":"get_forecast", …}]}}
```

Схемы никто не писал руками: они выведены из Go-структур, а описания полей взяты
из тегов. Поэтому список нельзя разойтись с кодом.

Потом сам вызов — `tools/call`:

```bash
curl -s -X POST http://localhost:8765/mcp \
  -H 'Content-Type: application/json' \
  -H 'Accept: application/json, text/event-stream' \
  -H 'MCP-Protocol-Version: 2025-11-25' \
  -d '{"jsonrpc":"2.0","id":2,"method":"tools/call",
       "params":{"name":"get_forecast","arguments":{"place":"Москва","days":3}}}'
```

Результат приходит дважды. Машинно — в `structuredContent`, числами. И текстом,
готовым к вставке в диалог с моделью:

```
Погода: Москва, Россия, часовой пояс Europe/Moscow, местное время 2026-09-22T19:30

Сейчас: слабый дождь, +15.9 °C (ощущается +16.9), влажность 91%, ветер 3 км/ч, осадки 0.3 мм/ч
Для наружных работ: идут осадки: наружные мокрые работы и окраску откладывают; высокая влажность (91%): сушка затянется

Прогноз по суткам:
  2026-09-22: слабый дождь, от +12.5 °C до +16.7 °C, вероятность осадков 93%, за сутки 8.2 мм, ветер до 10 км/ч
  2026-09-23: слабый ливень, от +13.4 °C до +17.2 °C, вероятность осадков 65%, за сутки 1.3 мм, ветер до 11 км/ч
  2026-09-24: слабый дождь, от +11.7 °C до +19.7 °C, вероятность осадков 89%, за сутки 7.0 мм, ветер до 18 км/ч
```

Строка «Для наружных работ» — единственное место, где сервер не пересказывает Open-Meteo,
а делает вывод. Так и задумано: 91% влажности — это факт, а «сушка затянется» — его смысл,
и знать перевод одного в другое должен тот, кто знает единицы измерения.

Ненайденное место поломкой не считается. Инструмент возвращает результат с `isError`,
а причина приходит текстом — её прочитает модель и переспросит человека:

```json
{"jsonrpc":"2.0","id":3,"result":{
  "content":[{"type":"text","text":"место не найдено: \"Тарабарск\""}],
  "isError":true}}
```

## Инструменты

### `get_forecast`

Фактическая погода и прогноз на несколько суток.

| Параметр | Тип | Обязательный | Что значит |
| --- | --- | --- | --- |
| `place` | строка | да | город или посёлок, где ведутся работы |
| `countryCode` | строка | нет | код страны из двух букв, если название встречается в нескольких странах |
| `days` | целое | нет | на сколько суток вперёд, 1–7; по умолчанию 3 |

### `find_place`

Поиск места по названию: координаты, страна, регион, часовой пояс. Нужен, когда
название неоднозначно — «Москва» есть и в России, и в Айдахо. Ради одной погоды
вызывать не обязательно: `get_forecast` ищет место сам и берёт первый вариант.

| Параметр | Тип | Обязательный | Что значит |
| --- | --- | --- | --- |
| `name` | строка | да | название населённого пункта |
| `limit` | целое | нет | сколько вариантов вернуть, 1–10; по умолчанию 5 |

Значения вне границ не отклоняются, а подрезаются: прогноз на семь суток в ответ
на просьбу о тридцати полезнее, чем отказ и лишний ход.

## Настройка

| Переменная | По умолчанию | Зачем |
| --- | --- | --- |
| `PORT` | `8080` | порт сервера |
| `API_TIMEOUT` | `15s` | потолок на один запрос к Open-Meteo |

`GET /health` отвечает `{"status":"ok"}` — по нему docker-compose понимает, что сервер
поднялся, ничего не зная про MCP.

## Зависимости

Одна прямая: [`github.com/modelcontextprotocol/go-sdk`](https://github.com/modelcontextprotocol/go-sdk) —
официальный Go SDK протокола. Он держит транспорт, рукопожатие и выводит json-схемы
инструментов из Go-структур. Остальное — стандартная библиотека.

## Тесты

```bash
go test ./...
```

В сеть не ходят: Open-Meteo подменяется `httptest`-сервером с записанными ответами,
а сам MCP проверяется настоящей клиентской сессией по транспорту в памяти — так под
проверку попадают и регистрация инструментов, и выведенные схемы, и валидация аргументов.
