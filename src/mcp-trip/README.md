# mcp-trip

MCP-сервер, который собирает план поездки по частям и публикует его в HTML.
Часть [Trip Planner](../trip-agent/README.md).

## Инструменты

| Инструмент | Что делает |
|---|---|
| `trip_create` | заводит план: город, страна, координаты, даты (не больше 14 дней), путешественники, допущения. Возвращает `trip_id` |
| `trip_set_budget` | записывает бюджет: сумму и валюту пользователя, сумму в местной валюте, курс, статьи расходов |
| `trip_add_day` | записывает день: погоду и 1–6 пунктов (время, место, описание, ссылка). Та же дата повторно заменяет день |
| `trip_publish` | публикует HTML. Неполный план не публикует и называет недостающие дни |
| `trip_get` | отдаёт план целиком, например для интерфейса |

Каждая запись проверяется на входе:
- `trip_id` должен соответствовать шаблону;
- даты дня — внутри поездки;
- длины текстов ограничены, управляющие символы убираются;
- ссылки допускаются только `http(s)`.

После публикации план не меняется. Имя файла сервер строит сам из города латиницей, даты и id,
например `stambul-2026-11-10-52135f1ff6.html`. HTML собирается через `html/template`:
самодостаточный, без скриптов, со светлой и тёмной темой.

## Данные

| Путь | Что там |
|---|---|
| `DATA_DIR/trips/trip_*.json` | планы |
| `OUT_DIR` (по умолчанию `DATA_DIR/out`) | опубликованные HTML |

## Запуск

```bash
docker build -t mcp-trip .
docker run --rm -p 8784:8080 -v "$PWD/data:/data" mcp-trip
```

## Тесты

```bash
go test ./...
```

Тесты проходят полный цикл: создание, бюджет, дни, отказ в публикации неполного плана,
публикация и запрет правок после неё. Отдельно проверяются отказы на чужом `trip_id`,
на пути вместо id, на дне вне дат, на опасной ссылке и на кривой валюте, а также
экранирование HTML.
